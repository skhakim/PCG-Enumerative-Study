# PCG Enumerative Study

Artifact for the extended abstract:

**SMT over Tree Metrics: Enumerating Pairwise Compatibility Graphs**

This repository contains code and shareable experimental artifacts for an exact SMT-based enumeration framework for Pairwise Compatibility Graphs (PCGs). The framework recognizes PCGs by encoding unknown leaf-to-leaf distances as integer variables constrained by tree-metric axioms and interval predicates.

The checker uses a staged exact pipeline:

1. star-PCG encoding,
2. caterpillar-PCG encoding,
3. general PCG encoding via a tree-metric distance matrix and the four-point condition.

This produces subclass-aware enumeration results: star-PCGs, caterpillar-only PCGs, general-only PCGs, and non-PCGs.

## Repository contents

```text
.
├── pcg_library_star_cat_gen.py      # Exact SMT checker for star/caterpillar/general PCG
├── pcg_enum.py                      # Parallel enumeration driver

├── filter_minimal_nonpcg_mp.py      # Multiprocessing minimal non-PCG filtering
├── 2and_check.py                    # 2-AND-PCG witness search using the PCG catalogue
├── jsonl_to_txt.py                  # Helper for converting JSONL graph outputs
├── results/                         # Enumeration outputs and summaries
└── README.md
```

## Minimal non-PCGs

A non-PCG `G` is minimal if every proper induced subgraph of `G` is a PCG. Equivalently, for every vertex `v`, the graph `G-v` is a PCG.

Using the complete `n=9` non-PCG catalogue, the `n=10` non-PCGs are filtered by vertex deletion.

| n | Non-PCGs | Minimal non-PCGs | Nonminimal non-PCGs |
|---:|---:|---:|---:|
| 8  | 7       | 7       | 0 |
| 9  | 1,960   | 1,482   | 478 |
| 10 | 953,801 | 417,539 | 536,262 |

## 2-AND-PCG check

A graph `G=(V,E)` is a 2-AND-PCG if there exist two PCGs `H1,H2` on the same vertex set such that

```text
E(G) = E(H1) ∩ E(H2).
```

Using the completed `n=10` PCG catalogue as a negative oracle, we checked all 953,801 non-PCGs on ten vertices. For each such graph `G`, the script found two disjoint edge-addition sets `A,B`, each of size at most 3, such that `G ∪ A` and `G ∪ B` are PCGs. Therefore every connected graph on at most ten vertices is a 2-AND-PCG.

## Requirements

The code was developed and run with:

- Python 3
- NetworkX
- Z3 Python bindings
- nauty/Traces tools, especially `geng` and `labelg` or `nauty-labelg`

Install Python dependencies with:

```bash
pip install networkx z3-solver
```

Install nauty/Traces separately and make sure `geng` and `labelg` are available in your `PATH`.

Check availability:

```bash
which geng
which labelg
which nauty-labelg
```

Depending on the system, the canonical labeling executable may be named either `labelg` or `nauty-labelg`.

## Basic usage

### Analyze a single graph6 string

```bash
python3 - <<'PY'
from pcg_library_star_cat_gen import analyze_one_graph6

g6 = "F?Beo"
result = analyze_one_graph6(g6, verbose=True)
print(result)
PY
```

The output record has the form:

```text
{
  "n": ...,
  "graph6": ...,
  "status": "sat-star" | "sat-caterpillar" | "sat-general" | "unsat",
  "mode": "exact",
  "edges": [...],
  "interval": [L, U] | None,
  "distance_matrix": [...] | None,
  "time_elapsed": ...,
  "note": ...
}
```

### Run enumeration

The enumeration driver processes connected unlabeled graphs generated by nauty and applies the staged checker.

Example:

```bash
python3 pcg_enum.py 8
```

For larger `n`, run inside `tmux` or another persistent shell:

```bash
tmux new -s pcg_enum_10
python3 pcg_enum.py 10
```

### Filter minimal non-PCGs

Sequential version:

```bash
python3 filter_minimal_nonpcg.py --n 10
```

Multiprocessing version:

```bash
python3 filter_minimal_nonpcg_mp.py \
  --n 10 \
  --jobs 120 \
  --chunk-size 1000 \
  --labelg-batch-size 20000 \
  --oracle-batch-size 100000 \
  --progress-every 50000
```

Expected output files:

```text
results/vert_10/minimal_non_pcg_10.jsonl
results/vert_10/nonminimal_non_pcg_10.jsonl
results/vert_10/minimal_non_pcg_10_summary.txt
```

### Run 2-AND-PCG catalogue check

```bash
python3 2and_check.py \
  --n 10 \
  --max-add-size 3 \
  --timeout-per-graph 60 \
  --jobs 120 \
  --candidate-batch-size 1000 \
  --oracle-batch-size 100000 \
  --progress-every 1000
```

The script uses the complete non-PCG list as a negative PCG oracle. It searches for two disjoint PCG supergraphs whose intersection is the target graph.

## Output format

Enumeration outputs are stored as JSONL files. Each line is one graph record.

Typical positive record:

```json
{
  "n": 10,
  "graph6": "...",
  "status": "sat-caterpillar",
  "mode": "exact",
  "edges": [[0,1], [0,2]],
  "interval": [3,4],
  "distance_matrix": [[0,3,4], [3,0,2], [4,2,0]],
  "time_elapsed": 0.123,
  "note": null
}
```

Typical non-PCG record:

```json
{
  "n": 10,
  "graph6": "...",
  "status": "unsat",
  "mode": "exact",
  "edges": [[0,1], [0,2]],
  "interval": null,
  "distance_matrix": null,
  "time_elapsed": 1.234,
  "note": null
}
```
